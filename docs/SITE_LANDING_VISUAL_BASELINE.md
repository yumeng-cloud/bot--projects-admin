### 4.1 示意清单（最低凑齐 4；标签供审图自检）

| 代号 | 示意 | 建议落点 | 长什么样（安静即可） |

| **V-Board** | 看板列示意 | Hero 右 或 B·一支队 | 3 列（待办/进行/完成）+ 2–3 张假 Issue 卡；中文标题；人/Agent 头像点 |
| **V-Seat** | 席位班底面板 | Hero 或 E | 席位表：角色名 + 在席/空席 + 人/Agent 区分；勿只 chip |
| **V-Multi** | 多机工位图 | D | 3 台「机」卡片 → 汇入「统一调度」；机上标席位名 |
| **V-Flow** | 四步流程条 | C | 横线连接 1–4，或迷你看板从空→有卡的前后态 |
| **V-Key**（可选） | 按需钥 | E | 一把钥 / 一席；「有则用 · 无则生」一行，勿堆墙码 |

### 4.2 加厚文案骨架（产品可微调用词，意思锁死）

**A2 为什么做**

- 标题：为什么做
- 正文：聊天窗管不住一支队——要占席、席间交付与验收，而不是多开几个对话。（「交接」=席间交付，**禁**写成换机续会话。）
- 示意建议：左「单聊窗」灰框 vs 右「席位班底」色框（小对比即可）

**C 怎么干活**

| # | 标题 | 正文 |
| --- | --- | --- |
| 1 | 建班底 | 按角色开席，人与 Agent 各就各位。 |
| 2 | 各机认领 | 不同电脑认领不同席位角色，并行干活。 |
| 3 | 看板推进 | 共享 Issue / Wiki / 上下文，进度同场可见。 |
| 4 | 统一调度 | 干完收束验收；拍板仍在人。 |

**D 分布式换机**

- 标题：多机就是一支队的工位  
- 正文：不是把同一会话挪到另一台电脑，而是让不同机器上的 Agent 认领不同角色，活在同一套调度下齐步走。

**E 席位与入场**

- 标题：钥匙按需，不堆墙  
- 正文：席位有人占用才算在席；入场钥匙有则用、无则生、替换才顶。决策与审查用强模型，写码席用轻量——档位后续可挂，结构已按席留好。

**F 底 CTA**

- 收束句：把 Agent 当同事组班，而不是当插件。  
- 按钮：登录
