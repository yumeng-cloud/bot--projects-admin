## 1. 要达成的丝滑场景

1. **空手上场**：新机装班底手册 → 贴 `ymk_`（我是谁）+ `ymt_`（进哪个队）→ 一次 `team join` → 拉班底、进合法席、handoff 还原现场。  
2. **扩编**：人不够时由**总指挥**（或后台 Admin）加席 / 签发入场码；新人只消费码，不自己乱开席。  
3. **活跃不顶替**：有人在干 → 一律进不去原席；只能加新员工席。旧人 leave / 标停工后才能补原席。  
4. **分布式**：多台电脑各干各的工作目录、拉最新、及时合；任务在看板；总指挥指派后**叫醒对应席位 Bot**被动开工。

---

## 2. 对象（拍死）

| 东西 | 形态 | 作用 |
|------|------|------|
| Bot Key | `ymk_…` | 身份；一人一把 |
| 团队入场码 | `ymt_…` opaque；库只存 hash | 定位 workspace+team；可吊销/限次/过期 |
| 席位 | team 下 slug 单活 | 空 / 活跃 / 停工·离职 |
| 续命 | `handoff get` | 权威；export 仅救场 |
| 唤醒 | Webhook → 席位例程 | 指派到我 → get → 干活；巡检兜底 |

**不做**：裸 UUID 当入场码；无 Key 只兑码进场；心跳自动判死；P0 上 WebSocket。

---

## 3. 主路径（人话）

**总指挥扩编**  
看任务量 → 后台「加席」或「复制入场码」（可勾：允许持码人在无空席时加新席）→ 把 `ymt_` 发给新人。

**新人机**  
装模板 → 配 `ymk_` → `ymbot team join --code ymt_… [--role frontend]`  
→ 兑换 → pull → 空席进 / 无空席且允许则加 `frontend-2` 再进 → handoff。  
活跃席 → 409，界面无「强行顶替」。

**日常远程**  
总指挥在看板把 Issue 派给某席 → Webhook 打到该席订阅 URL → 该机例程 `handoff get` 开工。丢包靠巡检补。

## 5. 关键技术点（已撞过）

- 兑换**只定位**，不 bind；join 编排在通道（可另加服务端一步，非必须）。  
- `allow_expand_seat` 写在 invite 上 → 扩编权在发码人，新人不能默契自开席。  
- 兼岗 = 新 slug（`frontend-2`），不同 slug 多行；同 slug 仍单活。  
- 席位 `status`：**显式** `empty|active|stopped|left`（停工可仍留痕，不只靠推断）。  
- Webhook 先做过滤扇出，不做席位私有 URL；重试队列另单，巡检兜底。

## 6. 验收（拍板后勾）

- J1 复制 `ymt_` / 兑换成功  
- J2 `team join` 一键还原  
- J3 活跃 409 无顶替  
- J4 停工补位有审计  
- J5 无空席且允许 → 新席；不允许 → 人话失败  
- J6 换机同码不抢活跃  
- J7 指派只叫醒对的席；误叫用巡检证明可兜住
