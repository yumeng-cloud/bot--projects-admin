## 0. 给总指挥（一句话）

Wiki 从「侧栏塞一棵树 + 中间写字」升级为 **「知识库工作台」**：空间可管、目录像书、正文像文档、属性像飞书文档属性条——管理有入口，阅读有节奏。

**流程**：产品体验定稿（本文）→ **视觉总监**立视觉规范 → React + UI视觉·审图执行 → 产品体验按 §7 勾选。

## 1. 现状为何「管不了 / 体验差」（根因）

| 根因 | 用户感知 | 对标产品怎么做 |
|------|----------|----------------|
| **空间管理藏死** | 只有小「+」和 Select 换空间，无成员/权限/归档叙事 | 飞书：知识库设置；语雀：团队库设置；Notion：Space settings |
| **目录=窄树塞件** | 像调试面板，不像「书的目录」 | 飞书/语雀：左栏固定宽、标题+层级清晰、拖拽排序 |
| **页面舞台仍像后台** | 属性芯片/工具条/空态互相抢视线 | Notion/飞书：标题最大，属性次之，正文为主 |
| **管理与写作同一平面** | 建库、建页、写正文、删页挤在一屏无层级 | 写作主路径 vs 管理次路径（设置抽屉/子页）分离 |
| **中文密度失控** | 要么挤、要么下半死白 | 手册：有序密度；树≥280；通栏满高 |

P0/P1 解决了「能建页、有芯片、通栏」；**没有**解决「知识库怎么管、怎么像中国文档产品」。

## 2. 对标摘要（定调，不抄像素）

### 2.1 飞书文档 / 知识库
- 左：知识库目录（可折叠、可搜索、可建子文档）
- 中：文档标题 + 协作信息 + 正文
- 知识库级「设置」独立入口（成员、权限、公开）
- 属性少而清晰；编辑即保存

### 2.2 语雀
- **库** 概念强：先选库，再进目录
- 目录树宽裕；「目录管理」可进更重的管理模式
- 正文阅读宽；顶栏操作克制

### 2.3 Notion 中文
- 页内属性（数据库属性感）用芯片/字段，不露 Form
- `/` 与块编辑非本轮；本轮仍 ByteMD，但壳要对

**本产品取舍**：Space ≈ 语雀「库」/ 飞书「知识库」；Page 树 ≈ 飞书目录；属性芯片保留但降权到标题下细轨；**管理进「知识库设置」**，不在写作面堆 Modal。

## 3. 信息架构（定稿）

```
工作区 (Workspace)
 └── Wiki 模块
      ├── 知识库列表（Spaces）          ← 管理面入口
      │     · 名称 / 描述 / 成员(P2.1) / 归档
      │     · 默认打开「最近」或「首个库」
      └── 知识库工作台（选中某个 Space）
            ├── 左：目录（树）
            │     · 搜索页
            │     · 新建页 / 新建子页 / 删除 / 重命名(P2.1)
            │     · 拖拽排序(P2.1，可后置)
            └── 右：页面舞台
                  · 顶栏：库名面包屑 · 保存态 · 分享/更多(⋯)
                  · 大标题
                  · 属性轨（项目 / Issue / 父级）— 芯片，默认折叠为单行
                  · 正文：阅读渲染 / 编辑 ByteMD
```

### 3.1 对象职责

| 对象 | 用户叫法 | 职责 |
|------|----------|------|
| Space | **知识库** | 一组页面的容器；有名、可描述；本轮 UI 必须能「新建/切换/（简）设置」 |
| Page | **页面** | 标题+正文+可选关联；挂在某库树下 |
| 属性 | **页面属性** | 关联项目、Issue、父页面——写作辅助，不是建页表单 |

### 3.2 两条路径（必须拆开）

1. **写作主路径**（90% 时间）：进 Wiki → 已选库 → 点目录页 → 读/写。零 Modal。  
2. **管理次路径**（偶尔）：「知识库」顶栏或空态 → 库列表 / 新建库 / 库设置抽屉。建库可用轻量抽屉或全页，**禁止**再把建库字段塞进写作 Modal。

## 4. 布局定稿（线框）

```
┌ AppNav │ 知识库顶条（当前库名 ▾ · 库设置 · 搜索全局可后置）──────────────┐
│        ├──────────────┬───────────────────────────────────────────────┤
│        │ 目录 280–320 │ 页面舞台（max 720–800 阅读栏，左缘对齐有呼吸）   │
│        │ 搜索         │ 面包屑：库名 / 祖先页…                          │
│        │ 树（行高≥36）│ 保存微文案 · 编辑 · ⋯（分享/删除/移到…）        │
│        │ + 新建页     │ 大标题                                         │
│        │              │ 属性芯片单行（可「展开」）                       │
│        │              │ 正文                                           │
│        └──────────────┴───────────────────────────────────────────────┘
└ 通栏 100dvh：侧栏+目录+舞台灰/白底贴视口底 ─────────────────────────────┘
```

### 4.1 关键态（新）

- 入口：顶条「知识库 ▾」旁 **「管理」** 或齿轮 → 右侧抽屉 / 子路由 `wiki/spaces`
- 内容：库列表表（名称、页数、更新时间、⋯ 归档）；「新建知识库」主按钮
- 单库设置（P2 最小集）：名称、描述；成员/权限标 **P2.1**（API 若已有则露出，没有则灰置「即将支持」勿假做）

### 4.2 目录态

- 宽 **≥280**（推荐默认 **300–320**）
- 行：图标 + 标题（可截断 ellipsis）+ hover ⋯（新建子页/重命名/删除）
- 当前页高亮；父子缩进清晰
- 空库：插画短文案 +「新建第一页」（沿用 P0 W8 精神）

### 4.3 页面舞台

- **阅读默认**；「编辑」进入编辑态（或点击标题/正文隐式进编辑——二选一，定：**显式编辑按钮**，免误触）
- 无「完成」紫主钮；保存 = 自动 / ⌘S + 微文案
- 删除、移到其他父级 → ⋯
- 属性：单行芯片；点击弹出选择器（已有 WikiPropChips 可迁）

### 4.4 明确砍掉的交互

- 写作区再弹「新建页面」三字段 Modal  
- 父页面 ID 手填  
- 目录与属性挤在同一窄列  
- 下半屏死白短壳

## 5. 与现有 API 的映射（少改后端）

| UI | API（已有优先） |
|----|-----------------|
| 知识库列表/新建 | spaces CRUD（`wiki-and-time.md`） |
| 目录树 | `wikiTree` |
| 新建页/子页 | `createWikiPage`（空标题草稿） |
| 正文保存 | PATCH autosave |
| 属性 | `project_id` / `issue_id` / `parent_id` |
| 成员权限 | **P2.1**：若后端无则 UI 只留入口文案，不假造 |

本轮 **允许** 为「库设置抽屉」补极薄 FE 路由；不强制新后端，除非缺字段挡「改名/描述」。
